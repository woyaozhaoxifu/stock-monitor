stock-monitor 闪退根治说明

2026-08-14 · 提交 c0b60fb · 本地累计 20 个 commit 待 push

为什么“突然”开始闪退

1
之前那版单实例锁用 tempfile 下的 PID 文件。但双击 start.bat 时，不同进程解析出的临时目录不一致——一个在 C:\Users\llia\AppData\Local\Temp，一个在 Git Bash 的 /tmp。锁文件“名同实异”，互相看不见，等于没加锁。
2
你看到闪退就再双击一下，结果又多开一个实例。多个 WebView2 实例同时抢同一个窗口类 Chrome_WidgetWin_0，互相把对方拖崩（C++ 级崩溃，try/except 拦不住）→ 黑框一闪即退。
3
崩溃残留的“僵尸 PID”+ Python 重定向到文件时 stdout 全缓冲（崩溃不 flush）→ stock-monitor.log 空白，没法定位。于是反复双击、反复多开、反复崩，陷入闪退死循环。

这次怎么根治的

  • 弃用 PID 文件锁，改用 Windows 内核命名互斥量 CreateMutex：与任何文件路径无关，进程崩溃时由操作系统自动释放，绝不留僵尸锁。
  • 同名互斥量全局唯一：只要有一个实例活着，后续双击一律被拦截并提示“已有实例在运行”，从源头消灭多开。
  • start.bat 加 -u 关闭 stdout 缓冲，今后真要崩，崩溃瞬间也能把原因写进日志，不再空白。
  • 保留上一轮的 --disable-gpu（规避远程桌面/集显下 GPU 渲染崩溃）。

真机验证结果 PASS

实例A 启动并持有互斥量 (PID 8221) 实例B 启动 → 检测到互斥量已存在 [看板] 已有实例在运行（窗口已被占用）。请直接使用已打开的窗口，或先关闭旧窗口后重试。 B_EXIT=1 ← 被正确拦截退出，未多开

结论：多开互崩的根因已彻底消除；本次仅改动启动/锁层，行情、画线、K线等功能无回归。

给你的操作指引

  • 照旧双击 start.bat 即可，不用任何额外操作。
  • 若不小心连点多次：只有第一个窗口会起来，其余会提示“已有实例在运行”并退出，不会再闪退成黑框。
  • 如果还出现闪退（极少数情况，可能指向 WebView2 Runtime 本身）：双击后程序目录会生成 stock-monitor.log，把它发我（或看最后几行红字），我就能精准定位。
提示：本次加固后若仍闪退，大概率是本机 WebView2 Runtime 需要更新/修复——可在系统里重装“Microsoft Edge WebView2 Runtime”，或我用日志进一步排查。
