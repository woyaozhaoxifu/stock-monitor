🛠️ 股票看板「闪退」修复说明

结论：闪退不是程序逻辑写错，而是原生窗口（pywebview / WebView2）在启动阶段崩溃，把整个程序一起拖死。已针对两个最可能的根因做了加固，并让「真闪退时也能留下错误线索」。

为什么会闪退？

  • ① 多个实例抢窗口类（最主要）
    反复双击 start.bat 会瞬间拉起多个 app.py，它们共用 WebView2 的窗口类，互相冲突 → 新窗口渲染进程崩溃 → Python 主进程跟着死。
    铁证：本地复现日志里出现 Failed to unregister class Chrome_WidgetWin_0. Error = 1411（典型的窗口类冲突）。
  • ② WebView2 GPU 硬件加速崩溃
    pywebview 在 Windows 上靠 Edge(WebView2) 内核。在远程桌面(RDP) / 集显笔记本 / 虚拟机下，GPU 硬件加速容易导致渲染进程崩溃 → 一闪即退（且 try/except 拦不住 C++ 级崩溃）。

这次改了什么

  • ✅ 单实例锁

    • 用进程 PID 文件确保同一时间只有一个实例在跑，从根本上消除①的窗口类冲突。再双击会被提示「已有实例在运行，请使用已打开的窗口」。

  • ✅ 禁用 WebView2 GPU 硬件加速

    • 注入 WEBVIEW2_ADDITIONAL_BROWSER_ARGS=--disable-gpu，改用软件渲染，规避②的远程桌面/集显崩溃（正常机器也能跑，只是略慢、更稳）。

  • ✅ 显式指定内核

    • webview.start(gui="edgechromium")，避免后端选错。

  • ✅ 启动日志落盘 + 不再一闪而过

    • start.bat 把所有输出和报错写到 stock-monitor.log；若仍异常退出，会停在窗口显示最后日志并等你按键，不再黑框一闪消失。

怎么用

照旧 双击 start.bat 即可。无需任何额外操作。

如果还是闪退（兜底诊断）：
1. 双击 start.bat 后，程序目录会生成 stock-monitor.log；
2. 把它发给我（或直接打开看最后几行红色报错）；
3. 我就能定位到 WebView2 的具体错误，进一步处理。

另外，若你是通过远程桌面连这台机器用的，本次「禁用 GPU」通常已能解决；若仍崩，多半是 WebView2 Runtime 需要更新（系统设置里修复/重装 Microsoft Edge WebView2 Runtime 即可）。

验证情况：单实例锁已真机验证通过（实例 A 存活时，实例 B 被正确拦截退出）；服务可正常启动、页面零 JS 错误。本次改动仅涉及启动/窗口层，不影响行情、画线、K线等功能。
